# 存储与数据架构 (Storage & Data Architecture)

## 1. AI 负载的 I/O 特征

AI 训练场景通过两种极端 I/O 模式同时向存储系统施压：

### 1.1 密集的小文件读 (Metadata Intensive)
*   **场景**: 训练开始阶段，DataLoader 读取大量图片、音频或文本片段。
*   **挑战**: 传统的 NAS 存储在面对亿级小文件时，元数据服务器 (MDS) 会成为瓶颈。
*   **优化趋势**: 将小文件打包成大文件 (如 TFRecord, WebDataset, Parquet)，减少元数据操作。

### 1.2 突发的高带宽写 (Bandwidth Intensive)
*   **场景**: 保存 Checkpoint。这是最关键的性能考量点。
*   **特征**: 
    *   所有 Worker 同时写入。
    *   写入量巨大（万亿参数模型 Checkpoint > 10TB）。
    *   要求极速完成（最好 < 1分钟），因为写入期间通常会阻塞训练。
*   **影响**: 存储吞吐不足会导致 GPU 空转等待，大大降低集群昂贵算力的利用率。

## 2. 存储分层架构

针对上述特征，AI Infra 通常采用分级存储架构：

```mermaid

    subgraph "Compute Nodes"

    subgraph "Hot Tier (Performance)"
        PFS[并行文件系统 (Lustre / GPFS / Weka)]

    end

    subgraph "Warm/Cold Tier (Capacity)"
        Obj[对象存储 (S3 / OSS / MinIO)]
    end

    GPU <==>|"Checkpoint (High BW Write)"| PFS
    GPU <==>|"Dataloader (Read)"| Cache
    Cache -.->|"Prefetch"| Obj
    PFS -.->|"Archive"| Obj
```

### 2.1 高性能层 (Performance Tier / Hot)
*   **用途**: 只有正在训练的数据集和最新的 Checkpoint。
*   **技术**: **并行文件系统 (Parallel File System)**。
    *   **Lustre**: 开源 HPC 存储标杆。客户端直连 OST (Object Storage Target)，数据条带化 (Striping) 分散存储，吞吐随节点线性扩展。
    *   **GPFS (IBM Spectrum Scale)**: 企业级商业方案，稳定性强，支持分级存储管理 (ILM)。
    *   **WEKA**: 新一代软件定义存储，专门针对 AI 优化的 NVMe Over Fabric，性能极高的小文件处理能力。

### 2.2 容量层 (Capacity Tier / Warm)
*   **用途**: 全量原始数据集，历史模型归档。
*   **技术**: **对象存储**.
    *   标准 S3 协议。成本低，扩展性几乎无限。
    *   **缺陷**: 最终一致性模型；首字节延迟较高；不支持 POSIX 接口（需要适配器）。

### 2.3 缓存加速层 (Caching Layer)
*   **用途**: 连接计算与对象存储的桥梁。
*   **技术**: **Alluxio** 或 **JuiceFS**。
    *   利用计算节点的本地 NVMe SSD 或独立缓存集群，缓存热点数据。
    *   提供标准的 POSIX 挂载点，让算法工程师像操作本地文件一样操作对象存储数据。

## 3. Checkpoint 优化技术

为了解决 Checkpoint 阻塞训练的问题，业界有多种优化方案：

1.  **异步 Checkpoint (Async Checkpoint)**:
    *   将模型权重先 copy 到 CPU 内存 (Pin Memory)，然后立刻恢复 GPU 训练。后台线程负责将 CPU 内存数据写入磁盘。
2.  **增量 Checkpoint (Incremental / Differential)**:
    *   只保存发生变化的参数（对于 Optimizer States 不一定适用，因为每个 step 都在变）。
3.  **专用 Checkpoint 格式**:
    *   **Safetensors**: 比 Pickle 更安全、更快的序列化格式，支持零拷贝 (Zero-copy) 加载。

## 4. 数据集管理与格式

### 4.1 数据格式演进
*   **Images/Files**: 最原始，对 inode 压力最大。
*   **TFRecord / LMDB**: 简单的 Key-Value 打包，解决了小文件问题，但不支持列式读取。
*   **Parquet / Arrow**: **推荐**. 列式存储，压缩比高，支持 Predicate Pushdown (只读取需要的列)，非常适合 NLP 语料。
*   **WebDataset**: 基于 Tar 包的流式格式，适合超大规模数据集的 Sharding 和 Shuffle。

### 4.2 数据加载优化 (Dataloader)
*   **预取 (Prefetching)**: CPU 提前加载下一个 Batch 到内存。
*   **解码加速**: 使用 NVIDIA DALI (Data Loading Library) 调用 GPU 直接解码 JPEG/MP3，减轻 CPU 负担。
