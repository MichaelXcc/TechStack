# SGLang 概述与定位

## 什么是 SGLang？

**SGLang (Structured Generation Language)** 是由 Berkeley 大学开发、LMSYS 组织托管的开源高性能 LLM 推理框架。它专注于提供低延迟、高吞吐的大语言模型和多模态模型服务。

```

│                        SGLang                                │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │ 前端 DSL    │  │  编译器     │  │  SGVM 运行时        │  │
│  │ (Python)    │──│  (优化器)   │──│  (高性能执行引擎)   │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 核心定位

### 1. 结构化生成语言 (Structured Generation Language)

SGLang 不仅是一个推理引擎，更是一种专门为 LLM 设计的领域特定语言 (DSL)：

```python
# SGLang 代码示例：多轮对话
@sglang.function
def multi_turn_chat(s, question1, question2):
    s += sglang.system("You are a helpful assistant.")
    s += sglang.user(question1)
    s += sglang.assistant(sglang.gen("answer1", max_tokens=256))
    s += sglang.user(question2)
    s += sglang.assistant(sglang.gen("answer2", max_tokens=256))
```

### 2. 高性能推理引擎

SGLang 在性能上的关键指标：

| 指标            | SGLang 表现              |
| --------------- | ------------------------ |
| 吞吐量          | 比 vLLM 提升 30-50%      |
| 首 Token 延迟   | 显著降低                 |
| KV Cache 复用率 | 高达 90%+                |
| 内存效率        | 通过 RadixAttention 优化 |

## SGLang 解决的核心问题

### 问题 1: KV Cache 浪费

**传统问题**: 相同前缀的请求重复计算 KV Cache
**SGLang 方案**: RadixAttention 自动检测和复用共享前缀

```
请求 A: "You are an AI assistant. What is Python?"
请求 B: "You are an AI assistant. What is Java?"
                    ↓
         共享前缀: "You are an AI assistant."
         RadixAttention 复用此部分 KV Cache
```

### 问题 2: 复杂 Prompt 编程困难

**传统问题**: 多轮对话、分支逻辑难以表达
**SGLang 方案**: 提供直观的 DSL 语法

```python
# 传统方式：手动管理 prompt 字符串
prompt = "..."
response1 = model.generate(prompt)
prompt += response1 + "..."
response2 = model.generate(prompt)

# SGLang 方式：声明式编程
@sglang.function
def chat(s):
    s += sglang.user("Hello")
    s += sglang.gen("response1")
    s += sglang.user("Follow up")
    s += sglang.gen("response2")
```

### 问题 3: 结构化输出难以保证

**传统问题**: JSON 等格式输出不稳定
**SGLang 方案**: 原生支持 Constrained Decoding

```python
# 强制输出 JSON 格式
s += sglang.gen("output", regex=r'\{"name": ".*", "age": \d+\}')
```

## 与其他框架对比

### SGLang vs vLLM

| 维度               | SGLang                           | vLLM                      |
| ------------------ | -------------------------------- | ------------------------- |
| **KV Cache 策略**  | RadixAttention (基于 Radix Tree) | PagedAttention (基于分页) |
| **前端语言**       | 原生 DSL                         | 无                        |
| **Prefix Caching** | 自动 + 高效                      | 手动启用                  |
| **结构化输出**     | 原生支持                         | 需 outlines 等工具        |
| **吞吐量**         | 更高 (30-50%)                    | 高                        |
| **社区成熟度**     | 快速发展中                       | 成熟                      |

### SGLang vs TensorRT-LLM

| 维度           | SGLang          | TensorRT-LLM  |
| -------------- | --------------- | ------------- |
| **优化层级**   | Runtime + Graph | 编译优化      |
| **灵活性**     | 高              | 需要预编译    |
| **硬件支持**   | 多平台          | NVIDIA 专属   |
| **部署复杂度** | 简单            | 较复杂        |
| **极限性能**   | 优秀            | 最优 (NVIDIA) |

## 总结

SGLang 的核心价值：

1. **RadixAttention**: 革命性的 KV Cache 复用机制
2. **前端 DSL**: 简化复杂 LLM 应用开发
3. **高性能运行时**: 全面优化的推理引擎
4. **广泛兼容性**: 支持多种硬件和模型
