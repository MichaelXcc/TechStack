# SGLang 核心架构

## 三元架构概览

SGLang 采用三层架构设计，实现从用户代码到高效执行的完整链路：

```
┌─────────────────────────────────────────────────────────────────────┐
│                         用户代码层                                   │
│    @sglang.function                                                 │
│    def my_program(s):                                               │
│        s += sglang.gen("output")                                    │
└────────────────────────────────┬────────────────────────────────────┘
                                 ↓
┌─────────────────────────────────────────────────────────────────────┐
│  ┌───────────────┐    ┌───────────────┐    ┌───────────────────┐   │
│  │   前端原语     │  → │   编译器/追踪   │ →  │   SGVM 运行时      │   │
│  │  (Primitives) │    │   (Compiler)  │    │   (Runtime)       │   │
│  └───────────────┘    └───────────────┘    └───────────────────┘   │
│         ↑                    ↑                      ↑               │
│   Python DSL          数据流图优化           高性能执行引擎          │
└─────────────────────────────────────────────────────────────────────┘
```

## 1. 前端原语 (Frontend Primitives)

### 核心原语列表

| 原语            | 功能         | 示例                                       |
| --------------- | ------------ | ------------------------------------------ |
| `gen`           | 异步生成文本 | `s += sglang.gen("output")`                |
| `select`        | 约束选择     | `s += sglang.select("choice", ["A", "B"])` |
| `fork`          | 分支流       | `forks = s.fork(2)`                        |
| `join`          | 合并流       | `s.join(forks)`                            |
| `extend` / `+=` | 追加内容     | `s += "Hello"`                             |
| `run`           | 执行程序     | `result = program.run(...)`                |

### 原语使用示例

```python
import sglang as sgl

@sgl.function
def complex_reasoning(s, question):
    # 1. 系统提示
    s += sgl.system("You are a helpful assistant.")

    # 2. 用户问题
    s += sgl.user(question)

    # 3. 分支探索多种思路
    forks = s.fork(3)  # 创建 3 个并行分支

    for i, fork in enumerate(forks):
        fork += sgl.assistant(sgl.gen(f"thought_{i}", max_tokens=200))

    # 4. 合并并总结
    s.join(forks)
    s += sgl.user("Based on the above thoughts, give your final answer.")
    s += sgl.assistant(sgl.gen("final_answer", max_tokens=500))

# 执行
result = complex_reasoning.run(question="What is machine learning?")
print(result["final_answer"])
```

### 3.1 推理调度器 (Inference Scheduler)

```python
class InferenceScheduler:
    """
    核心职责:
    1. 管理请求队列
    2. 决定批处理策略
    3. 协调 Prefill 和 Decode 阶段
    """

    def schedule_batch(self):
        # 根据内存状况动态调整批大小
        available_memory = self.get_available_memory()

        # Prefill-Decode 分离调度
        prefill_batch = self.select_prefill_requests()
        decode_batch = self.select_decode_requests()

        return self.optimize_batch(prefill_batch, decode_batch)
```

### 3.2 自适应控制器 (Adaptive Controller)

```python
class AdaptiveController:
    """
    动态监控和调优:
    1. KV Cache 使用率监控
    2. 批大小自动调整
    3. 内存压力响应
    """

    def monitor_and_adjust(self):
        kv_usage = self.get_kv_cache_usage()

        if kv_usage > 0.9:  # 内存压力大
            self.trigger_eviction()  # 淘汰低优先级 cache

        if kv_usage < 0.5:  # 内存充裕
            self.increase_batch_size()  # 增加批大小
```

## 数据流全景

```
用户请求
    │
    ↓
┌──────────────────────────────────────────────────────────────────┐
│ 1. Tokenization                                                   │
│    "Hello, how are you?" → [15496, 11, 703, 527, 499, 30]        │
└──────────────────────────────────────────────────────────────────┘
    │
    ↓
┌──────────────────────────────────────────────────────────────────┐
│ 2. Prefix Matching (RadixAttention)                               │
│    检查 Radix Tree，找到可复用的 KV Cache                         │
│    ┌─────────────────────────────────────┐                        │
│    │ Matched: "Hello, how" (4 tokens)    │ → 复用                 │
│    │ New: "are you?" (3 tokens)          │ → 计算                 │
│    └─────────────────────────────────────┘                        │
└──────────────────────────────────────────────────────────────────┘
    │
    ↓
┌──────────────────────────────────────────────────────────────────┐
│ 3. Prefill Phase                                                  │
│    计算新 token 的 KV Cache                                       │
│    使用 FlashAttention 加速                                       │
└──────────────────────────────────────────────────────────────────┘
    │
    ↓
┌──────────────────────────────────────────────────────────────────┐
│ 4. Decode Phase (Auto-regressive)                                 │
│    循环生成 token 直到结束                                        │
│    ┌─────────────────────────────────────┐                        │
│    │ Step 1: Generate "I"                │                        │
│    │ Step 2: Generate "am"               │                        │
│    │ Step 3: Generate "fine"             │                        │
│    │ Step 4: Generate "."                │                        │
│    │ Step 5: Generate [EOS]              │ → 结束                 │
│    └─────────────────────────────────────┘                        │
└──────────────────────────────────────────────────────────────────┘
    │
    ↓
┌──────────────────────────────────────────────────────────────────┐
│ 5. Update Radix Tree                                              │
│    将新计算的 KV Cache 插入 Radix Tree 供后续请求复用             │
└──────────────────────────────────────────────────────────────────┘
    │
    ↓
返回响应
```

## 关键设计决策

### 1. 为什么使用 Radix Tree？

| 数据结构       | 前缀查找 | 插入     | 内存   | SGLang 选择 |
| -------------- | -------- | -------- | ------ | ----------- |
| Hash Table     | O(n)     | O(1)     | 高     | ❌          |
| Trie           | O(m)     | O(m)     | 中     | ❌          |
| **Radix Tree** | **O(m)** | **O(m)** | **低** | **✅**      |

Radix Tree 压缩了 Trie 的节点，更适合存储 token 序列。

### 2. Prefill-Decode 分离

```
传统方式:
┌────────────────────────────────────────┐
│ Request│ Prefill ────────> Decode ──>  │
│   1    │ [████████████]   [█][█][█]    │
│ Request│         Prefill ─> Decode ──> │
│   2    │         [████████] [█][█][█]  │
└────────────────────────────────────────┘
问题: Prefill 阻塞其他请求

SGLang 优化:
┌────────────────────────────────────────┐
│  Prefill Batch    │  Decode Batch      │
│  ┌────────────┐   │  ┌────────────┐    │
│  │Req1 Prefill│   │  │Req3 Decode │    │
│  │Req2 Prefill│   │  │Req4 Decode │    │
│  └────────────┘   │  │Req5 Decode │    │
│                   │  └────────────┘    │
└────────────────────────────────────────┘
优势: 分离调度，互不阻塞
```

### 3. 零开销 CPU 调度器

```python
# SGLang 的调度器设计原则
class ZeroOverheadScheduler:
    """
    设计目标:
    1. 最小化 Python GIL 影响
    2. GPU 和 CPU 操作重叠
    3. 预取和异步执行
    """

    def run(self):
        while True:
            # 异步预取下一批请求
            next_batch = self.prefetch_async()

            # 当前批在 GPU 执行
            self.execute_on_gpu(current_batch)

            # 零等待切换
            current_batch = next_batch
```

## 总结

SGLang 架构的核心优势：

1. **前端 DSL**: 提供表达力强的编程模型
2. **编译优化**: 自动检测优化机会
3. **RadixAttention**: 革命性的 KV Cache 复用
4. **分离调度**: Prefill-Decode 解耦
5. **自适应控制**: 动态资源管理
