# ADR-004: GPU 调度方案选型

## 元数据

- **状态**: 🟢 已采纳
- **决策日期**: 2026-01-28
- **决策者**: AI 基础设施架构组

## 背景

### 问题描述

随着 AI 训练和推理任务的增长，需要在 Kubernetes 集群中实现高效的 GPU 资源调度。核心需求包括：

- GPU 共享：多个 Pod 共享同一张 GPU
- 资源隔离：显存和算力的细粒度隔离
- 拓扑感知：考虑 GPU 与 NVLink/NVSwitch 拓扑

### 约束条件

- 需支持 NVIDIA GPU（H100/A100/V100）
- 需与现有 Kubernetes 调度器集成
- 需要有生产环境验证案例

## 备选方案

### 方案 A: HAMi + Volcano

**描述**: HAMi 提供 GPU 虚拟化和共享，Volcano 提供高级调度能力

| 维度 | 评价                                          |
| ---- | --------------------------------------------- |
| 优点 | GPU 共享、显存隔离、Gang Scheduling、拓扑感知 |
| 缺点 | 需要同时部署两个组件                          |
| 成本 | 开源免费，CNCF 项目                           |
| 风险 | 低，已有大规模生产案例                        |

### 方案 B: NVIDIA GPU Operator + MIG

**描述**: NVIDIA 官方方案，使用 MIG 实现 GPU 分区

| 维度 | 评价                               |
| ---- | ---------------------------------- |
| 优点 | 官方支持、硬件级隔离               |
| 缺点 | 仅支持 A100/H100 MIG、分区粒度固定 |
| 成本 | 免费，但需要支持 MIG 的 GPU        |
| 风险 | 低，官方方案                       |

### 方案 C: 阿里云 cGPU

**描述**: 阿里云的 GPU 容器共享方案

| 维度 | 评价               |
| ---- | ------------------ |
| 优点 | 成熟的企业级方案   |
| 缺点 | 与阿里云绑定、闭源 |
| 成本 | 商业许可           |
| 风险 | 中等，供应商锁定   |

## 决策

**选择**: 方案 A - HAMi + Volcano

### 决策理由

1. **灵活性**: HAMi 支持任意粒度的 GPU 切分，不受 MIG 限制
2. **生态整合**: Volcano 与 Kubernetes 原生调度器无缝集成
3. **功能完整**: 支持 GPU 共享、显存隔离、拓扑感知、Gang Scheduling
4. **开源开放**: CNCF 项目，避免供应商锁定
5. **社区活跃**: 有持续的更新和良好的社区支持

### 权衡考量

- MIG 提供硬件级隔离更安全，但灵活性不足
- HAMi 是软件隔离，需要信任用户不会恶意突破

## 影响

### 正面影响

- GPU 利用率预计提升 40-60%
- 支持更灵活的资源分配
- 训练任务可以使用 Gang Scheduling

### 负面影响

- 需要部署和维护额外组件
- 需要培训团队使用新的资源申请方式
