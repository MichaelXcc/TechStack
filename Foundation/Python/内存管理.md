# Python内存管理 (Memory Management)

## 💡 核心概念
Python的内存管理机制主要由三部分组成：**引用计数机制**（主）、**垃圾回收机制GC**（辅，解决循环引用）、**内存池机制**（优化小对象分配）。

## 🔍 机制详解

### 1. 引用计数 (Reference Counting)
每个对象内部都有一个 `ob_refcnt` 字段记录被引用的次数。
- **增加**：对象被创建、被赋值给变量、作为参数传递、放入容器中。
- **减少**：引用变量被销毁、被赋予新值、从容器中移除。
- **回收**：当引用计数降为0时，立即回收内存。
- **优点**：实时性高，处理回收快。
- **缺点**：无法解决**循环引用**问题。

### 2. 垃圾回收 (Garbage Collection)
专门用于检测和打破**循环引用**（Reference Cycles）。
- **分代回收 (Generational GC)**：Python将所有对象分为三代（第0代、第1代、第2代）。
    - 新建对象放入第0代。
    - 经历过GC检测且存活的对象，移入下一代。
    - 代数越高，GC扫描频率越低（基于假设：存活越久的对象越不可能在近期死亡）。
- **标记-清除**：辅助引用计数，用于识别不可达的循环引用对象组。

### 3. 内存池 (Pymalloc)
为了减少频繁申请/释放内存（malloc/free）带来的系统开销，Python引入了内存池机制。
- **小对象 (<512字节)**：使用 `pymalloc` 分配器，在内存池中分配（基于Arena, Pool, Block三级结构）。
- **大对象**：直接调用系统的 `malloc`。

## 💻 代码与调试

### 查看引用计数
```python
import sys
a = []
b = a
print(sys.getrefcount(a)) # 输出 3 (a, b, getrefcount参数)
```

### 强制GC
```python
import gc
gc.collect() # 强制运行全代垃圾回收
```

### 弱引用 (Weak Reference)
`weakref` 模块允许引用对象但不增加引用计数，常用于缓存（Cache）场景，避免对象因缓存而无法被回收。
```python
import weakref

class A: pass
a = A()
r = weakref.ref(a)
# r() 返回对象 a，如果不存活则返回 None
```

## ⚠️ 性能优化建议
1. **避免循环引用**：手动解除引用，或使用 `weakref`。
2. **使用 `__slots__`**：对于只要固定属性的类，定义 `__slots__` 可以禁止创建 `__dict__`，大幅节省内存。
3. **对象复用**：对于高频创建销毁的对象，考虑对象池模式。
