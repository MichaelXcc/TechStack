# AI 编码技能评估体系

## 📋 概述

> [!WARNING] 核心问题
> 不会用 AI 的人使用 AI 工具，不仅无法提效，反而会增加额外负担：
>
> - 花大量时间调试 AI 生成的错误代码
> - 盲目信任导致引入 Bug
> - 不理解生成的代码，后期维护困难

本文档定义 **AI 编码技能评估标准**，帮助判断开发者是否具备使用 AI 工具的能力。

---

## 🎯 评估等级

| 等级   | 名称   | 要求                   | 授权              |
| ------ | ------ | ---------------------- | ----------------- |
| **L0** | 未达标 | 未通过基础评估         | ❌ 不建议使用     |
| **L1** | 基础级 | 掌握基本使用方法       | ✅ 可使用基础功能 |
| **L2** | 熟练级 | 能高效使用 Agent 模式  | ✅ 可使用全部功能 |
| **L3** | 专家级 | 能编写 Skill、指导他人 | ✅ 可培训他人     |

---

## 📊 L1 基础级评估（准入门槛）

### 必备能力清单

| 序号 | 能力项          | 评估标准                             | 权重 |
| ---- | --------------- | ------------------------------------ | ---- |
| 1    | **Prompt 编写** | 能写出清晰、完整、有上下文的 Prompt  | 25%  |
| 2    | **代码审查**    | 能识别 AI 生成代码中的明显问题       | 25%  |
| 3    | **错误判断**    | 能判断 AI 输出是否正确，不盲目采纳   | 20%  |
| 4    | **工具操作**    | 熟悉基本工具操作（补全、对话、编辑） | 15%  |
| 5    | **问题定位**    | AI 输出有问题时，能定位并手动修复    | 15%  |

### 评估方式

#### 实操测试（60分钟）

| 任务            | 要求                             | 评分 |
| --------------- | -------------------------------- | ---- |
| 任务1：功能开发 | 使用 AI 完成一个简单功能         | 30分 |
| 任务2：代码审查 | 审查 AI 生成的代码，找出问题     | 30分 |
| 任务3：Bug 修复 | 使用 AI 辅助修复一个 Bug         | 20分 |
| 任务4：代码解释 | 让 AI 解释一段代码，并验证正确性 | 20分 |

#### 通过标准

| 指标       | 要求                               |
| ---------- | ---------------------------------- |
| 总分       | ≥ 70 分                            |
| 代码审查   | ≥ 20 分（不能盲目信任）            |
| 无严重问题 | AI 生成的代码不得有明显 Bug 被忽略 |

---

## 📊 L2 熟练级评估

### 能力要求

| 序号 | 能力项         | 评估标准                           |
| ---- | -------------- | ---------------------------------- |
| 1    | **Agent 模式** | 能使用 Agent 模式完成多文件任务    |
| 2    | **上下文管理** | 能有效管理上下文，提供必要信息     |
| 3    | **效率提升**   | 使用 AI 后效率有明显提升（≥20%）   |
| 4    | **质量控制**   | AI 辅助代码的 Bug 率不高于手写代码 |
| 5    | **场景判断**   | 能判断何时该用/不该用 AI           |

### 评估方式

| 方式     | 内容                          |
| -------- | ----------------------------- |
| 项目评估 | 评估过去 1 个月的 AI 使用效果 |
| 效率数据 | 对比使用前后的任务完成速度    |
| 质量数据 | 对比 AI 辅助代码的 Bug 率     |

---

## 🚨 不合格信号（红线）

以下任一情况，判定为 L0（不建议使用 AI）：

| 红线         | 表现                         |
| ------------ | ---------------------------- |
| **盲目信任** | 直接采纳 AI 输出，不做审查   |
| **无法判断** | 分不清 AI 输出的对错         |
| **效率下降** | 使用 AI 后任务完成更慢       |
| **严重 Bug** | AI 辅助代码引入生产问题      |
| **过度依赖** | 离开 AI 无法完成基本开发任务 |

## 📋 快速自检清单

开发者可使用以下清单自我评估：

```markdown
## AI 编码能力自检

### 基础能力

- [ ] 我能写出清晰的 Prompt，包含上下文和期望
- [ ] 我能识别 AI 生成代码中的逻辑错误
- [ ] 我不会盲目复制 AI 输出，会先审查
- [ ] 我能判断 AI 回答是否正确
- [ ] AI 出错时，我能手动修复

### 进阶能力

- [ ] 我能使用 Agent 模式完成复杂任务
- [ ] 我知道什么任务适合用 AI，什么不适合
- [ ] 使用 AI 后，我的效率确实提升了
- [ ] AI 辅助的代码质量不低于我手写的

### 红线检查

- [ ] 我从不盲目信任 AI 输出
- [ ] 我没有因为 AI 代码导致过生产问题
- [ ] 离开 AI 我依然能正常开发
```

**评估结果**：

- ✅ 基础能力全部勾选 → L1 达标
- ✅ 进阶能力 ≥3 项 → L2 达标
- ❌ 红线任一项未通过 → L0 不达标

## 📅 评估执行建议

### 评估周期

| 类型     | 时机          | 方式                |
| -------- | ------------- | ------------------- |
| 准入评估 | 使用工具前    | L1 实操测试         |
| 定期评估 | 每季度        | 效率数据 + 质量数据 |
| 升级评估 | 申请 L2/L3 时 | 综合评估            |

### 不达标处理

| 等级    | 处理方式                         |
| ------- | -------------------------------- |
| L0      | 暂停使用权限，参加培训后重新评估 |
| L1 降级 | 限制高级功能，加强培训           |
