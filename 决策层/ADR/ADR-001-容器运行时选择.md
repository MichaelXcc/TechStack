# ADR-001: 容器运行时选择 containerd

## 元数据

- **状态**: 🟢 已采纳
- **决策日期**: 2026-01-28
- **决策者**: 云原生架构组

## 背景

### 问题描述

随着 Kubernetes 1.24+ 版本正式移除 dockershim，我们需要在集群中选择一个新的容器运行时来替代 Docker。

### 约束条件

- 需兼容现有 OCI 镜像格式
- 需支持 CRI 接口
- 需要有良好的社区支持和长期维护
- 对现有工作流程影响最小

## 备选方案

### 方案 A: containerd

**描述**: CNCF 毕业项目，被 Docker 和 Kubernetes 官方推荐

| 维度 | 评价                                    |
| ---- | --------------------------------------- |
| 优点 | 轻量级、性能好、CNCF 毕业项目、社区活跃 |
| 缺点 | 调试工具不如 Docker 完善                |
| 成本 | 开源免费，迁移成本低                    |
| 风险 | 低，已被大规模生产验证                  |

### 方案 B: CRI-O

**描述**: 专为 Kubernetes 设计的轻量级运行时

| 维度 | 评价                     |
| ---- | ------------------------ |
| 优点 | 专为 K8s 设计、轻量      |
| 缺点 | 生态不如 containerd 完善 |
| 成本 | 开源免费                 |
| 风险 | 中等，社区相对较小       |

### 方案 C: Docker + cri-dockerd

**描述**: 通过 cri-dockerd 继续使用 Docker

| 维度 | 评价                           |
| ---- | ------------------------------ |
| 优点 | 对现有工作流无影响             |
| 缺点 | 额外组件、性能开销、长期不推荐 |
| 成本 | 需要额外维护 cri-dockerd       |
| 风险 | 高，长期可能被废弃             |

## 决策

**选择**: 方案 A - containerd

### 决策理由

1. **行业标准**: containerd 是 Kubernetes 生态的事实标准
2. **性能优势**: 相比 Docker 减少了调用层，启动速度更快
3. **社区支持**: CNCF 毕业项目，有强大的社区和商业支持
4. **兼容性好**: 完全兼容 OCI 镜像，现有镜像无需修改

### 权衡考量

- 虽然 Docker CLI 更易用，但 containerd 的 ctr/nerdctl 工具可以满足日常需求
- 开发环境可继续使用 Docker Desktop，生产环境使用 containerd

## 影响

### 正面影响

- 资源占用降低约 10-15%
- Pod 启动速度提升约 10%
- 与 Kubernetes 原生集成更好

### 负面影响

- 需要学习新的调试工具
- CI/CD 管道可能需要调整
