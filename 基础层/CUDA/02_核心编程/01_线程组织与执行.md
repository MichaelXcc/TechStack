# 线程组织与执行

## 1. 软件逻辑 vs 硬件物理

| 软件概念 (Software) | 硬件概念 (Hardware) |
| :--- | :--- |
| **Grid** | 整个 Kernel 执行范围 |
| **Block** | **SM (Streaming Multiprocessor)** |
| **Thread** | **CUDA Core / SP** |
| **Warp (逻辑组)** | **Warp (物理执行单元)** |

## 2. Warp (线程束)

Warp 是 GPU 执行指令的基本单位。
- 在当前的 NVIDIA 架构中，一个 Warp 包含 **32** 个线程。
- **SIMT (Single Instruction Multiple Threads)**: Warp 内的所有线程在同一时刻执行相同的指令。

### Warp Divergence (线程束发散)
当 Warp 内的线程遇到条件分支 (`if-else`) 时：
1.  如果所有线程都走同一分支，效率最高。
2.  如果部分走 `if`，部分走 `else`，则发生 **Divergence**。
    - 硬件会先执行 `if` 分支（此时 `else` 线程被禁用）。
    - 然后执行 `else` 分支（此时 `if` 线程被禁用）。
    - 最后重新汇合。
    - **后果**: 性能显著下降。

> [!WARNING] 优化建议
> 尽量避免在 Warp 内产生不同的分支路径。如果必须分支，尽量让相邻的32个线程走相同的路径。

## 3. 延迟隐藏 (Latency Hiding)

GPU 没有像 CPU 那样大的 Cache 和 复杂的乱序执行逻辑，它通过 **大规模多线程** 来隐藏延迟。

- 当一个 Warp 在等待内存读取（高延迟操作）时，SM 会迅速切换到另一个 **Ready** 状态的 Warp 去执行。
- 这种切换的开销几乎为零（Zero-overhead context switch），因为寄存器文件是分区的，上下文始终驻留在芯片上。

### Occupancy (占用率)
- 指 SM 上实际活跃的 Warp 数量与最大支持 Warp 数量的比值。
- 高 Occupancy 意味着有更多的 Warp 可以用来掩盖延迟，通常能带来更好的性能。
- 受限于：寄存器使用量、Shared Memory 使用量。

## 4. 线程同步

### `__syncthreads()`
- **Block 级同步栅栏**。
- 保证 Block 内所有线程都到达该点后，才继续执行后续指令。
- **由轻到重**: Warp 内隐式同步 (SIMT) -> Block 内显式同步 (`__syncthreads`) -> Grid 级同步 (Kernel结束)。

> [!NOTE] 
> CUDA 不支持 Grid 全局同步（除非使用 Cooperative Groups 等高级特性或结束 Kernel）。
